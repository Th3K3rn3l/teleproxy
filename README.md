# Teleproxy

HTTP(S)/TCP proxy через Yandex Telemost (SFU WebRTC). Позволяет обходить файрволы, используя DataChannel как туннель между клиентом и сервером.

## Как это работает

```
Клиент (SOCKS5) ←→ Yandex SFU ←→ Сервер (исходит запросы в интернет)
```

Оба конца подключаются к одной конференции Telemost и обмениваются данными через SFU.

## Требования

- Go 1.21+
- Браузер с аккаунтом на Яндексе (для создания конференции)

## Быстрый старт

### 1. Собрать

```bash
git clone https://github.com/Th3K3rn3l/teleproxy.git
cd teleproxy
go build ./cmd/server
go build ./cmd/client
```

### 2. Создать конференцию

Откройте https://telemost.yandex.ru в браузере, создайте новую конференцию, скопируйте ссылку вида:

```
https://telemost.yandex.ru/j/abc123def
```

### 3. Запустить сервер (на VPS)

```bash
./server -url=https://telemost.yandex.ru/j/abc123def
```

### 4. Запустить клиент (на ПК)

```bash
./client -url=https://telemost.yandex.ru/j/abc123def
```

Клиент поднимет SOCKS5 прокси на `127.0.0.1:1080`.

### 5. Настроить браузер

**Firefox:** Настройки → Сеть → Настройка соединения → Ручная конфигурация прокси → SOCKS5 → `127.0.0.1:1080`.

**Chrome:** `chrome --proxy-server=socks5://127.0.0.1:1080`

## Параметры

### Сервер

| Флаг | По умолчанию | Описание |
|------|-------------|----------|
| `-url` | — | Ссылка на конференцию Telemost |
| `-uid` | — | Yandex UID (опционально, для REST API) |
| `-session` | — | Session_id cookie (опционально, для REST API) |
| `-name` | `ProxyServer` | Имя в конференции |

Сервер автоматически переподключается при обрыве.

### Клиент

| Флаг | По умолчанию | Описание |
|------|-------------|----------|
| `-url` | — | Ссылка на конференцию Telemost |
| `-uid` | — | Yandex UID (опционально, для REST API) |
| `-session` | — | Session_id cookie (опционально, для REST API) |
| `-name` | `ProxyClient` | Имя в конференции |
| `-socks` | `127.0.0.1:1080` | Адрес SOCKS5 прокси |

## Как это устроено

- Конференцию создаёте вы в браузере под своим аккаунтом Яндекса
- Сервер и клиент подключаются по ссылке
- Если указан `-uid`, приложение вызывает REST API для получения credentials (рекомендуется)
- Если `-uid` не указан, приложение пробует подключиться напрямую через WebSocket (может не работать)
- Сервер держит соединение вечно (автопереподключение при обрыве)
- В одной конференции может быть сколько угодно клиентов

## Ограничения

- UDP в SOCKS5 — частично (только CONNECT + DNS через TCP)
- STUN только (`stun.rtc.yandex.net:3478`), TURN не используется
- Для подключения через WebSocket без REST API могут потребоваться credentials (зависит от настроек конференции)
